## 抽出方法

元のvalidationは18,668対局、1,863,669局面で、学習と着手列hashで分離済みです。
R2800〜2999は全体に4,109局面、72対局あり、従来の50,000局面標本には127局面だけが含まれていました。
今回はvalidation全体から抽出し直しました。
train、diagnostic、testは混ぜていません。

自Rが既知の0以上3000未満を200刻みに区切ります。
手数は絶対手数で1〜20、21〜40、…、141〜160、161以上の9帯です。
各手数帯で全R帯が確保できる局面数の最小値を取り、その構成比を各R帯2,000局面へ比例配分しました。
端数は小数部が大きい順に配り、セル内でseed 20261120による非復元無作為抽出を行います。
手数帯の内訳は全R帯で同じですが、帯の内部の細かな手数までは一致させていません。

## 評価と不確かさ

605,000更新EMA、CUDA float32、TF32無効、全合法手で正規化、温度1です。
PyTorch 2.11.0+cu130、NumPy 1.26.4で集計しました。
同じ局面で自Rだけを100、300、…、2900へ変更し、相手R、時計、最大8局面の履歴は観測値に固定します。
2900は比較した入力の上限です。
これより高い入力Rは未測定で、最適値を確定した結果ではありません。
棋力帯の性能図は、同じ30,000局面へ観測された自Rを入力した結果です。
自然頻度50,000局面の全体成績、手数帯、条件省略の評価は別の集合として維持しています。

bootstrapは対局単位で2,000回再抽出し、局面等重みの平均と対応のある入力間の差を計算します。
各区間は個別の95%区間で、15候補の最良値を選ぶことに対する多重比較補正はしていません。
同一対局内の相関を考慮しますが、同一プレイヤーに由来する相関までは補正していません。
対局数はR帯によって異なり、局面内容、相手R、持ち時間の分布も一致させていません。
手数帯と標本数を揃えた比較であり、条件付けの因果効果や実棋力の校正を保証するものではありません。

128局面のCPUとの照合では第一候補が全件一致し、着手確率の最大絶対差は1.24e-6未満でした。
重みと評価データのSHA-256、全セルの数値、抽出枠と区間は[集計JSON](metrics/preview-step-0605000-rating-matrix.json)に保存しています。
局面ごとの情報や対局IDは含めません。

## 再生成

privateな抽出データと同名の来歴JSONを用意して実行します。
抽出ツールはtrainerの`scripts/experiments/prepare_matched_rating_validation.py`です。

```console
uv sync --group analysis
uv run python tools/evaluate_rating_matrix.py --model models/preview-step-0605000 --dataset /path/to/matched-rating-validation.npz --selection-info /path/to/matched-rating-validation.json --per-band 2000 --cache work_dir/matched-metrics.npz --output docs/metrics/preview-step-0605000-rating-matrix.json
uv run python tools/plot_metrics.py docs/metrics/preview-step-0605000.json --rating-matrix docs/metrics/preview-step-0605000-rating-matrix.json
```

上の既定はCPUです。CUDA対応PyTorchでは`--device cuda --batch-size 32`を追加できます。
cacheは局面単位のためローカル専用です。公開するのは集計JSONと図だけです。
日本語フォントが必要です。
